# Витрина: экраны, карточки, поля выпуска, плашки, тема

Витрина https://tzi-850-sber.pages.dev — шесть экранов на одном выпуске `/api/model` (контракт
`sber-v1`, поля — `docs/PAYLOAD.md`, ниже «П§N»). Методика чисел — `docs/MODEL.md` («М§N»).
Источник правды — `web/app.js` (экраны — `SCREENS`, карточки — функции `…Card`); правила
держат тесты витрины `tests/test_web_*.py` и Node-проверки `tests/web/web_app_check.mjs`
(витрина с заглушкой DOM `tests/web/dom_stub.mjs`), `tests/web/web_release_text.mjs` (текст
экранов без служебных строк) и `tests/web/web_functions_check.mjs` (дверь данных) на фикстуре
`tests/fixtures/payload-sample.json`; контракт выпуска — тесты ядра `tests/test_core2_*.py`
(`model/payload.py::validate`). Файлы и владение — `docs/INTERFACES.md`.

**Основа кода — витрина Ленты** (`lenta-850/web/`, `functions/`): ядро 850oa без литералов
компании, имя и тикер — из выпуска, колл Мертона снят, дверь под публичный репозиторий,
дисклеймеров нет. **Из X5** — округление печати половиной вверх, время МСК, читаемость
(кегль ≥ 12,5 px, контраст рядов ≥ 3 : 1), битый адрес не роняет старт, карточки цены и
дивидендов, полосная шкала `stripChart`. Карточки ритейла сняты, банковские добавлены.
Имена функций ниже — функции `lenta-850/web/app.js` («Л») и `x5-850/web/app.js` («X»);
«нов.» — новая функция; «как есть» / «правка» — перенос без изменений / с правкой полей и
подписей. Сводка переноса — приложение.

## 2. Правила витрины

* **Числа — только из выпуска**, формул модели во фронте нет. Единственный пересчёт — ползунок
  λ «рыночные ставки как есть ↔ свой макро-взгляд» (П§0.1): центр прогона = низ + λ·(верх −
  низ), квантиль тип 7, печать к `fair_value.headline.print_step` половиной вверх
  (`roundHalfUp` из X вместо `roundHalfEven` Л — так печатает ядро, П§0.3). Всё прочее при
  λ ≠ книги — строки `fair_value.headline.by_lambda` и `fair_value.bank_first_line.by_lambda`
  (`atLambda`). Прочие экраны показывают λ книги. Тест
  `test_the_front_computes_nothing_but_the_books_lambda_rule`.
* **Арифметика отображения** — только форматирование, доли → проценты, концы «значение ±
  ошибка», минимум–максимум, счётчики, дни до даты от `meta.valuation_date`, возраст выпуска по
  часам зрителя. Потенциал к цене, доходности, P/B, запас норматива — поля выпуска.
* **Литералов банка в `app.js` нет** (тест `test_the_front_carries_no_company_literals` с
  шаблонами имени, тикеров и регномера): имя — `company(d)` (`meta.company.name`), тикеры —
  `tickers(d)` (нов.: `meta.company.tickers`) и `ticker(d)` (правка: `meta.company.main_ticker`).
  Подписи миров, режимов, сценариев капитала, слоёв, гейтов, флагов и нормативов — `title`/`name`
  из выпуска, не словари `app.js`. **Нормативы — только `capital.titles`** (`n20`, `n11`,
  `n11_observed`, `n1_0`, `n1_2`: «Н20.0 группы», «Н1.0 банка»…) — и в карточках наблюдения
  (`capital.observed`, РСБУ по месяцам); ключ метрики выпуска (`n20_0` в условии дивиденда)
  витрина переводит той же подписью (`metricTitle`). Литерала «Н1.x»/«Н20.x» в `app.js` нет
  (тест `test_ratio_labels_come_from_capital_titles`). Имя банка — только статическим текстом в
  `index.html` и `404.html`. Так ядро витрины остаётся копируемым для следующих банков (DESIGN §7).
* **Названия эталонов** — из выпуска: `nowcast.retro.titles`, затем `next_report.benchmarks[].name`
  и `nowcast.quarter.by_target.*.benchmarks[].name` (`benchNames`); ключ эталона
  (`ras_bridge`, `prev_quarter`) на экран не попадает.
* **Доли вклада в полосу** (`contributions[].share`, `judgements.rows[].share`) меньше 1 % —
  «< 1 %» без упорядочивания (погрешность долей ≈ 0,5 п.п. при 2 000 прогонах, М§10; `shareText`).
  У книги все оси в полосе; ось вне полосы (`judgements.rows[].in_band = false`) печатается словами
  «вне полосы» **той же мерой, что правило М§10**: на сколько фиксация таких осей сдвигает заголовок
  и порог гейта (`judgements.off_band_shift`, `offBandNote`), а не «вклад < 1 %». Число осей полосы в
  подписи распределения — строки суждений с `in_band` (с осями-словарями), не длина `contributions`.
* **Служебного текста на экране нет** (П§0.2): базисы — словарь `BASIS` (все коды П§0.2, в том числе
  «норматив ЦБ» и «прогноз сектора»); коды политики дивидендов — `codeText` (`CODE_WORDS`: база,
  делитель, округление, правило нехватки; `true`/`false` — «да»/«нет»); опора книги ЧПД — `refText`;
  метки клеток `W/r/s` и коды периодов в текстах ядра (флаги, сообщения и коридоры гейтов, строки
  сверки) — словами выпуска (`wordsText`, `cellName`, `periodLabel`); единицы `date` и `period` —
  датой и подписью периода (`formatByUnit`). Свободный текст (`ruText`) получает десятичную запятую,
  но версии и ссылки остаются как есть: «книга 1.2», «book-1.6», «М§4.11», «п. 6.4», «Н20.0»
  (`RU_DECIMAL`; тест гоняет то же выражение в Python). Одна вероятность печатается одной функцией
  (`pBelowText`: от 1 % — целые, меньше — два знака). Строки ядра, которые печатаются предложением
  (сообщение гейта, записка о сроке политики, уравнение нау-каста), получают заглавную букву и
  точку (`sentence(upperFirst(…))` — после `ruText`, иначе «п. 6.4» станет дробью); после
  многоточия точка не ставится. **Слова для владельца правит источник строки** (книга, факты,
  ядро), а не маска на витрине: кортеж, e-нотацию, метку класса допущения, путь к листу, рабочую
  пометку, дату без года («30.09» читается дробью) витрина не чинит — их ловит общая проверка
  `web_release_text.mjs` (§7). Исключение одно — запись миров: печатается «запись семейства 850,
  версия N» (`worldsRecord` берёт номер из `worlds.source.origin`), имя репозитория записи на
  экран не идёт.
* **Единицы — коды П§0.2**, по величине значения единица не угадывается: строки суждений, обратного
  расчёта и входов — `formatByUnit` (`years` — «4 года», «1,6 года»; `number` — число, `pp` — п.п. со знаком);
  плитки индикаторов — `indicatorValue` (`bn` — млрд ₽, `price` и `rub` — ₽, `share` и `pct` — %,
  `level` и `count` — число). **Ось-словарь** (вероятности режимов, веса миров) печатает диапазон
  парами концов по ключам — «Кризис 10,0 → 25,0 %» (`rangeText`, `isDict`; порядок концов — как у
  точки на краях; нет конца — «—»; в «торнадо» — ключ с наибольшим ходом). Строка обратного
  расчёта без оси книги (концы диапазона равны) диапазона не печатает (`reverseRange`).
* **Слово после числа — по напечатанному числу** (`plural(n, формы, знаков)`): целое — «1 год»,
  «2 года», «5 лет», «21 день»; число с дробной частью — родительный единственного («1,6 года»,
  «2,5 года»). Срок в годах печатает одна функция (`yearsText`: знаков — сколько есть, до одного):
  оси суждений, ввод избытка капитала, узлы кривой. Счётчики «Проверок» согласованы с числом
  («1 поднятый флаг», «4 сработавших гейта из 19», «0 нарушенных инвариантов из 14»), число клеток
  гейта — словом («3 клетки»), сокращения «кл.» нет; у гейта, который сравнивает миры целиком
  (`cells` = 0), счёт клеток не печатается — только масса.
* **Сверка с контрольной моделью — в единице строки по виду допуска.** Столбцы уровня: доля
  (`pct`, `share`) — в %, сдвиг доли (`pp`: σ0, спреды, кредитная маржа) — в п.п., как на «Расчёте»;
  деньги — млрд ₽ и ₽. Относительные разность и допуск (`tol_kind: rel`) — в процентах; абсолютные —
  в единице строки (доли и сдвиги — в п.п.) со знаками допуска: знаков — до первой значащей цифры
  допуска и не меньше принятого у единицы (допуск 1·10⁻⁶ доли — «0,0001 п.п.»), глубже четырёх —
  степенью десяти. Разность мельче знаков своего допуска печатается нулём, пока строка в допуске
  (шум счёта 6·10⁻¹⁷ на экран не идёт); у строки вне допуска разность не прячется.
* **Источник — как пришёл из выпуска.** Историю дивидендов подписывает `dividends.history[].src`
  (`sourcesByYear`): один источник на все годы — строкой, два-три — с годами («2013–2020,
  2022–2025 — …; 2021 — …»), больше — раскрывающимся списком. Слова пишут факты: решение собрания
  или наблюдательного совета и раскрытие эмитента, сверка с брокерским календарём — словами; имён
  методов и полей API и пометок о токене ни в выпуске, ни в витрине нет (общая проверка текста, §7).
* **`null` — не ноль, и на графике тоже.** Линия идёт по непрерывным участкам: через нераскрытое
  значение не проводится, одиночная точка рисуется точкой (`linesChart`). Нулевой столбец несёт
  подпись «0» и цель подсказки, `null` не рисуется; значение меньше единицы подписано с двумя
  знаками (`columnsChart`). Плитка без числа не рисуется — причина печатается строкой
  (раскрытая чувствительность ЧПД); пустой интервал — словами («интервал не оценён»).
* **Легенда собирается из нарисованного:** запись легенды появляется вместе с элементом графика
  (интервал и точка нау-каста, эталоны, гайденс, экс-даты, смена книги, линии рынка), пунктирная
  и точечная линии — такими же ключами (`key-model2`, `key-market2`, `key-neg2`, `key-neg3`,
  `key-dash`). Проверка — `web_app_check.mjs`: каждой записи легенды соответствует элемент той же
  карточки (цвет, пунктир, кружок или полоса).
* **Чувствительности языка банка — целыми рублями** (₽ на 1 п.п. ROE, на 0,1 п.п. CoR и ЧПМ):
  оценщик срединных прогонов точнее не даёт (М§8.3, §10); местный наклон «что даст отчёт» —
  с одним знаком до 10 ₽.
* **Причины деградации** (`live.degraded`) печатаются словами; адрес в причине — только именем
  сервера (`reasonText`: запрос с датами читателю не нужен). Дата или период в одном поле
  (`nowcast.admission.earliest_decision`) — по-русски (`dayOrPeriod`).
* **Единицы периода** — словарь `PERIOD_WORDS` (Л) дополняется месяцем: `meta.period_unit`
  (`quarter`, модель и МСФО) и `meta.input_unit` (`month`, РСБУ и формы ЦБ). `periodLabel`
  (Л, правка) понимает `2026Q3` → «3 кв. 2026», `2026M09` → «сентябрь 2026», год — как есть.
* **Поля — объявленные:** каждое `d.<блок>` — в `REQUIRED_TOP_LEVEL` (тест
  `test_frontend_reads_only_declared_blocks`), поля — из П§2; снятые поля (П§6) витрина не
  читает.
* **Две категории акций.** Одна справедливая стоимость на обе (М§8.2); главный тикер —
  `meta.company.main_ticker`: P(ниже рынка), перцентиль и цвет теплокарты — к нему; вторая
  категория — второй линией рынка (пунктир `--market`) на распределении, цене за 12 месяцев и
  истории оценки, вторым числом в потенциале и доходности.
* **Устойчивость:** блока нет — карточка так и пишет (`missing`); упал экран или график —
  «Экран не отрисовался» / «График не отрисовался» внутри одной карточки, остальное живо.
  Графики — свой SVG в настоящих пикселях карточки (`chart`), у главных — кнопка «Таблица»
  (`withTable`) с теми же числами.
* **Диагностики** «что в цене», язык банка и «что даст отчёт» считаны для числа, которое назвал
  выпуск (`target: "median"`): слова экрана («медиана») — по этому полю.
* **«Стоимость капитала» — только ставка** (М§2): V0 в мосте и слоях — «оценка капитала»
  (заголовок строки — из выпуска); у терминала названа база: «PV терминала RI» (остаточный
  доход), «Доля терминала DDM» (дивидендная модель).
* **Дисклеймеров нет** (правило владельца; тест `test_there_are_no_disclaimers_on_the_screen`):
  ни «не рекомендация», ни «не вердикт» ни в подвале, ни в «Как читать».
* **Время — по Москве с пометкой «МСК»** (X `mskDay`): момент сборки, время сделки, даты сборки.
  Вероятности режимов — с одним знаком (сумма 100 %), P(ниже рынка) меньше 1 % — с двумя.
* **Базис подписан** у каждого отчётного числа («МСФО группы», «РСБУ банка», «упр.», «движок», «норматив ЦБ», «прогноз сектора», «рынок»);
  упр. ЧПМ, CoR и CIR — поля `*_mgmt` выпуска (`paths.annual[].cir_mgmt` — A7), пути CoR режимов в
  базисе движка — `cor_engine`; мост во фронте не применяется.

## 3. Экраны

Порядок — как в семействе, от ответа к основаниям: Оценка → Что в цене → Расчёт → Ближайший
отчёт → Капитал и дивиденды → Допущения. Адреса — `#overview`, `#market`, `#model`, `#report`,
`#capital`, `#book`; `OLD_HASHES` ведёт `#debt` и `#money` → `#capital`, `#value` → `#overview`,
`#priced` → `#market`; незнакомый или битый хэш открывает «Оценку» и заменяет адрес без новой
записи истории (`screenFromHash` Л + `syncHash` X).

### 3.1. Оценка (`#overview`)

Шапка экрана (`screenHead`): бровь «Справедливая стоимость акции · <тикеры через точку> ·
<дата оценки>» из `meta.company.tickers` и `meta.valuation_date`.

| Карточка (функция) | Что рисует | Поля выпуска |
|---|---|---|
| Герой (`hero` Л, правка) | печатаемая медиана «≈ N ₽» и точная; полосы 80 % и 50 %; вердикт — P(справедливая ниже цены главного тикера) с метром (форма семейства; у главного и второго тикера, в подписи метра и в таблице — одна функция `pBelowText`); строка потенциала «к SBER +x %, к SBERP +y %»; надстрочник с тикерами | `fair_value.headline` (`printed_median`, `median`, `printed_band80`, `printed_band50`, `p_below_market`, `market_percentile`, `upside`, `by_lambda`), `market.prices`, `meta.company`, `meta.book_version`, `meta.valuation_date` |
| Распределение и ползунок λ (`distributionChart`, `centresAt`, `headlineAt`, `pointAt`, `printedPoint`, `atLambda`, `lambdaNow`, `bookLambda` — Л; правка: линии рынка по всем тикерам) | плотность 2 000 центров, полосы, «ящик» P10–P90, медиана, линии рынка (главный — сплошная, вторая категория — пунктир), ромб точки; ползунок λ с шагом `lambda_step`; таблица-двойник | `fair_value.headline` (`low_draws`, `high_draws`, `print_step`, `own_macro_confidence`, `lambda_step`, `market_by_ticker`, `by_lambda`), `fair_value.rates_view` |

## 5. Тема, CSP, палитра, знак, телефон

* **Дизайн-система 850oa** («белые карточки на тёплой бумаге», тёмная тема; токены
  `styles.css`) с правками X: минимальный кегль 12,5 px (брови, подписи графиков), контраст
  рядов ≥ 3 : 1 к карточке в обеих темах (`--third` #179f6f в светлой, `--series-neutral` для
  нейтрального ряда). Палитра графиков: синий — модель, оранжевый — рынок (вторая категория —
  тот же цвет пунктиром), бирюзовый — эталоны и третий ряд, красный — отрицательная сторона
  (разрыв капитала, урезанный дивиденд, минус в водопаде); текст — в цветах текста, не ряда.
  Цвета графиков — только через CSS-переменные: смена темы не требует перерисовки.
* **Без фирменного стиля эмитента** (DESIGN §8): ни логотипа, ни фирменной зелёной гаммы;
  знак — нейтральный глиф семейства (`favicon.svg` и знак шапки — один рисунок).
* **Тема:** с 20:00 до 07:00 по часам зрителя страница открывается тёмной (правило владельца для
  всех панелей); днём без ручного выбора — системная; ручной выбор вечером живёт до закрытия
  вкладки (`sessionStorage`), днём — в `localStorage`. Правило — одним инлайн-скриптом в
  `web/index.html` (`window.__theme`: `isNight`, `resolve`, `remember`, окно [20, 7]),
  разрешённым в CSP по sha256. Ключи хранилища — общие для банковских витрин
  (`tzi-theme`, `tzi-theme-tonight`): хранилище у каждого сайта своё (разные адреса), а
  одинаковый скрипт даёт одинаковый хэш CSP у всех банков семейства.
* **CSP** — одна политика на статике (`web/_headers`) и на функциях (`functions/_middleware.js`,
  `THEME_SCRIPT_HASH`), как у Ленты: `default-src 'self'`; скрипты — свои и инлайн-скрипт темы
  по sha256; стили — свои и инлайн; картинки — свои и `data:`; `connect-src 'self'`;
  `font-src 'self'`; `object-src 'none'`; `base-uri 'none'`; `form-action 'none'`;
  `frame-ancestors 'none'`; плюс `X-Content-Type-Options: nosniff`, `Referrer-Policy:
  no-referrer`, `Permissions-Policy`. Хэш считается по LF-версии скрипта (Python на Windows
  пишет CRLF — грабля Ленты); после правки скрипта — пересчитать в обоих местах:
  `test_theme_script_hash_matches_csp` печатает строку на замену, равенство политик —
  `test_csp_is_the_same_in_headers_and_middleware`. Функции — только для `/api/*`
  (`web/_routes.json`); `_middleware.js` держит границу `/api/`: разрешён только `model`,
  прочее — JSON 404.
* **Со сторонних адресов не грузится ничего:** шрифт системный, графики — свой SVG и HTML-полосы
  без библиотек, сборки нет.
* **Телефон (375 px):** широкие таблицы едут внутри карточки с закреплённой первой колонкой,
  число не переносится никогда, свободный текст — второй раскрываемой строкой, мелкого шрифта
  (< 12,5 px) нет. Второстепенные карточки длинных экранов («Ближайший отчёт», «Расчёт») на
  ≤ 720 px сворачиваются в «ещё N карточек» — числа при этом не прячутся, раскрываются одним
  нажатием. Шапка карточки с переключателем или ссылкой на ≤ 480 px переносится: заголовок и
  подзаголовок — во всю ширину, переключатель — строкой ниже (иначе заголовку оставалась половина
  ширины; замер `narrowHeads`, §7); на широком экране переключатель занимает свою ширину.

## 6. Дверь данных `/api/model`

`functions/api/model.js` — схема Ленты: основной источник — GitHub Pages репозитория данных
`temp-zero-inode-850-sber-data` (`latest.json` ветки `release` с минутной меткой в запросе,
`cacheTtl` 60 с), запасной — raw той же ветки, третий — последняя годная копия в кэше края.
Адреса и схема — **переменные Pages** в `wrangler.toml` (`[vars]`; INTERFACES §8), в коде функции
нет имени банка — дверь переносится в следующий банк правкой одного файла:

| Переменная | Что | Значение (`wrangler.toml`) |
|---|---|---|
| `DATA_SCHEMA` | схема выпуска; ответ источника с другой `schema` — отказ источника | `sber-v1` |
| `DATA_PAGES_URL` | основной источник: `latest.json` ветки `release` на GitHub Pages (минутная метка в запросе) | Pages репозитория данных |
| `DATA_RAW_URL` | запасной: raw той же ветки | raw ветки `release` |

Выкладка (§8) везёт их из `wrangler.toml`; в панели Cloudflare их не правят. Нет переменной (или
адрес не `https://`) — 503 `upstream unavailable` без подзапросов. Подзапрос ограничен 8 с
(отмена по таймеру).
Строгий разбор JSON и проверка `schema` = `sber-v1` (на переходе контракта — П§8); ответ с
`Last-Modified` = `meta.published_at`, сильным `ETag` `"<sha12>.<секунды>"`,
`Cache-Control: max-age=60`, заголовком `x-data-source` (`pages` / `raw` / `edge-cache`); 304
на `If-None-Match`; 503 `not published yet` — оба источника ответили 404; 503 `upstream
unavailable` — прочие отказы без копии края; 405 на методы кроме GET и HEAD. `/api/model` без
User-Agent (или с пустым) отвечает 403 `user-agent required` — правило держит сама функция,
сборщики и сторож шлют свой UA (DESIGN §6.2). Поведение — `tests/web/web_functions_check.mjs`
(Node, подменённые `fetch`, `caches` и часы).

## 8. Выкладка

`npx wrangler@4.135.0 pages deploy web --project-name tzi-850-sber --branch main` из корня рабочей
копии на коммите `main` (функции wrangler берёт из `functions/`). **Проект Pages создаётся один
раз владельцем** — в панели Cloudflare или через API, с производственной веткой `main`: команда
выкладки проект не создаёт, а `wrangler 4.135 pages project create` создаёт Worker, а не проект
Pages (DESIGN §7). Для этой витрины проект `tzi-850-sber` уже создан; перед выкладкой —
`npx wrangler@4.135.0 pages project list` (в списке есть `tzi-850-sber`), шаг и приёмка двери —
`ops/README.md` §5 п. 11 и §8. ID аккаунта и токен Cloudflare в репозиторий не пишутся. Метка
`--branch` обязана совпадать с производственной веткой, иначе выкладка молча уйдёт в предпросмотр.
Меняется контракт — сначала данные (новый выпуск с новыми полями), потом витрина (П§8).
