# Перезаякоривание: перенос книги на отчёт квартала

Методика — `docs/MODEL.md` §15.2 («М§»); здесь — пошаговая процедура дня отчёта (§1), формат
файла отчёта квартала (§2), формулы переноса (§3), разложение скачка (§4). Инструмент —
`ops/tools/reanchor.py`, тесты — `tests/test_reanchor.py`. Факты нового якоря в канон собирает
`ops/tools/build_facts.py` (`data/facts/SCHEMA.md` §3–§5).

Книга стоит на одном квартале. Отчёт МСФО закрывает её первый прогнозный квартал, и якорь
переходит на него: четыре раза в год, по одному кварталу (пропущенный отчёт — сначала своим
кварталом, потом следующим). Перенос якоря сам по себе оценку двигать не должен: **факт, равный
ожиданию модели, даёт ту же оценку, что прокатка прежней книги** (инвариант «механика ≈ 0»).
Всё, что помнит прошлое или привязано к якорю, переносит инструмент, а не ручная правка.

Инструмент не правит ни книгу, ни факты, ни ядро: он пишет кандидата в каталог (по умолчанию
`var/reanchor/<квартал>/`). Внутри репозитория он пишет только под `var/` — любой другой каталог
рабочей копии (`data/`, `model/`, `docs/`, `tests/`, `ops/`, `web/`…) — отказ. В канон кандидата
переносят авторы книги и фактов.

**Режим передачи ставки один — `keep`** (он же по умолчанию; решение ведущего,
`docs/DECISIONS.md`): скаляры пути σ0_A, σ0_L, φ_A, φ_L прежней книги сохраняются, цели и доли
пересчитываются к новому якорю (§3.5). `--transmission resolve` — только диагностика: кандидат
книги и фактов при нём не пишется.

## 1. День отчёта: пошаговая процедура

Исполнитель — Claude по просьбе владельца в день отчёта (или ведущий); ближайший отчёт — МСФО за
2026 год, по календарю фактов 25.02.2027, якорь `2026Q4` (перенос на `2026Q3` — книга 1.4,
28.10.2026). Ниже `<период>` — закрываемый квартал;
команды — из корня репозитория, `BANK_HANDOFF_DIR` — папка передачи (листы этапа 1, первичка).
Объём работы — один рабочий день: документы и листы — утро, кандидат и приёмка — середина дня,
канон, выпуск и записи — вечер.

### 1.1. До отчёта: сухой прогон

За несколько дней до отчёта и утром в день отчёта, на текущих `main`, книге и фактах:

```
python -B ops/tools/reanchor.py --expected var/reanchor/expected.json
python -B ops/tools/build_facts.py --expected var/reanchor/expected.json --out var/reanchor/facts-canon
python -B ops/tools/reanchor.py --facts var/reanchor/expected.json --out var/reanchor/dry \
       --valuation-date <сегодня> --band <прогонов> --compare-facts var/reanchor/facts-canon
```

Ожидаемый отчёт — «факты = ожидание модели»: в нём нет ни одного факта, и шаблоном для настоящих
чисел он не служит. Приёмка сухого прогона — по `var/reanchor/dry/REANCHOR.md` (критерии — §1.5,
строки 1–8): механика в допуске, сюрприз факта — ровно ноль, инварианты ядра выполнены. Таблица
«Проверки ядра на кандидате» заранее показывает гейты, которые сработают на новом якоре при
отчёте без новостей: объяснения к ним готовятся до отчёта. Сухой прогон, который не проходит,
разбирается до отчёта: какое-то правило, помнящее прошлое, не перенесено.

**Отчёт за первый квартал года — квартал шока** (якорь стоит на четвёртом квартале, год шока
кризиса — следующий). Прогноз наблюдения в нём двугорбый — шок либо случился, либо нет, — и
ожидаемый отчёт, среднее двух горбов, «отчётом без новостей» не является: такого CoR не ждёт ни
один режим (§3.7). Под таблицей разложения сухой прогон печатает абзац «Квартал шока режима …» со
второй строкой «обучение» — на отчёте без шока (наблюдение — ожидание прочих режимов). Заранее
известный сдвиг точки читается по ней; в журнал версии записываются оба числа.

### 1.3. Какие числа внести

Числа нового квартала вносятся **в листы этапа 1 в папке передачи**, а не в файл отчёта квартала:
файл отчёта (§2) сборщик пишет сам из собранных фактов. Основной путь — инструменты этапа 1
(разбор отчётности и презентации); **лист квартала** — проверка полноты и ручной ввод строк,
которые разбор не дал. Шаблон листа — `data/facts/sheets/<период>.csv` (колонки — `SCHEMA.md`
§5): в каждой строке `value`, `doc`, `page` — что внести, `prev_value`, `prev_doc`, `prev_page`
— значение, документ и страница той же строки в прошлом отчёте. Заполненный лист кладётся в

### 1.4. Команды

```
# 1. полнота (якорь ещё прежний): в колонке value пусто — строки нового квартала в листах ещё нет
python -B ops/tools/build_facts.py --check --sheet-template var/reanchor/sheet-<период>.csv

# 2. кандидат фактов и файл отчёта квартала (сверки сборщика обязаны сойтись)
python -B ops/tools/build_facts.py --anchor <период> --out var/reanchor/facts-<период> \
       --report var/reanchor/report-<период>.json

# 3. кандидат книги, разложение скачка, сверка рабочих фактов кандидата с фактами сборщика
#    (--observation <файл> — только по решению книги о подмене наблюдения закрытого квартала, §3.1)
python -B ops/tools/reanchor.py --facts var/reanchor/report-<период>.json --out var/reanchor/<период> \
       --band <прогонов> --compare-facts var/reanchor/facts-<период> [--observation <файл>]

# 4. канон фактов — после приёмки кандидата (§1.5)
python -B ops/tools/build_facts.py --anchor <период>
python -B ops/tools/build_facts.py --check
python -B ops/tools/build_facts.py --check --sheet-template data/facts/sheets/<следующий период>.csv
```

Дата оценки кандидата — `published` отчёта (или `--valuation-date`); `<прогонов>` — число
прогонов полосы книги (`valuation.uncertainty.draws`), для пробы хватает 200. Коды возврата
`reanchor.py`: 0 — сделано; 1 — отказ с причиной (отчёт не того квартала, негодный файл, запись
внутри репозитория вне `var/`, механика вне допуска — кандидат при этом записан для разбора, в
канон его не переносят).

### 1.5. Критерии приёмки кандидата

Читаются в `var/reanchor/<период>/REANCHOR.md` и в выводе сборщика. Не выполнен хотя бы один из
1–8 — кандидат в канон не идёт.

| № | Критерий | Где смотреть |
|---|---|---|
| 1 | код возврата `reanchor.py` — 0; в заголовке нет строки «ОТКАЗ» | вывод команды 3 |
| 2 | **механика:** стоимость каждой клетки на своём пути — в пределах 0,1 % (кроме клеток перезаряженного режима на смене года якоря); точка строки «механика» — в 0,1 % цены | «Разложение скачка», «Механика по клеткам» |
| 3 | скаляры пути σ0_A, σ0_L, φ_A, φ_L кандидата равны скалярам прежней книги (расхождение — не больше 0,0002 п.п.) | «Производные величины», строка «передача ставки» |
| 4 | якорь модели воспроизводит Н20.0 и Н1.1 отчёта | там же, строка «поправки „норматив − расчёт“» |
| 5 | вероятности режимов кандидата равны вероятностям прежней книги с тем же наблюдением; ни один режим не ниже пола | там же, строки «вероятности режимов» (на настоящем отчёте — и прежняя книга с тем же наблюдением, что у кандидата), «пол вероятности режима» |
| 6 | на сухом прогоне: «сюрприз факта» — ровно ноль; «выпуклость» точки — не больше 0,2 шага печати, строка медианы «механика и выпуклость» — не больше половины шага | «Разложение скачка», «Заголовок — медиана полосы» |
| 7 | инварианты ядра на кандидате выполнены все; у каждого сработавшего гейта есть или готовится объяснение | «Проверки ядра на кандидате» |
| 8 | сверка фактов: «Расхождений нет» — ядро читает из рабочих фактов кандидата и из фактов сборщика одно состояние якоря; все сверки сборщика — «ок» | «Сверка фактов кандидата…»; вывод команды 2 |
| 9 | строка «сюрприз факта» объяснима отчётом (и подменой наблюдения, если она была, §3.1): знак и порядок согласуются со строками «что даст отчёт» прежнего выпуска (упр. ЧПМ и CoR квартала против ожидания и нейтральных значений) | «Разложение скачка»; раздел «Отчёт» витрины |

Строка «обучение» — не критерий: при смеси режимов наблюдение, равное ожиданию, двигает
вероятности (М§12); её величина записывается в журнал. В квартале шока (§1.1) рядом с ней стоит
строка «отчёт без шока» — в журнал идут обе.

### 1.6. Перенос в канон

1. **Факты** — команды 4 из §1.4; `calendar.json` и `peers.json` — руками (`SCHEMA.md` §3): прошедшие
   события подтверждены, даты отчёта становятся прецедентами, горизонт календаря — не короче
   12 месяцев; `docs/FACTS.md` — числа нового якоря. История рядов индикаторов
   `data/indicators/seed/` — снимок на запуск сервера, с отчётом не пересобирается: новые месяцы и
   кварталы ряды сервера получают от сборщиков, а смена файлов истории перезаливает их ряды
   (`indicators/collect.py`, `ensure_seed`); тесты сверяют её с листами и мостом фактов на её
   периодах (`tests/test_ind_seed.py`). Факт квартала в журнал прогнозов —
   `python -m indicators.collect record-actual …` (`docs/MANUAL.md` §10.4).
2. **Книга** — порядок новой версии (`data/assumptions/README.md`): готовый шаблон с правками
   кандидата — `var/reanchor/<период>/assumptions_template.yaml` (комментарии сохранены) —
   становится `data/assumptions/assumptions_template.yaml`; комментарии у изменённых ключей
   переписать на новые числа и источники (кандидат меняет значения, а не комментарии); поднять
   `meta.version`, `meta.date`, `meta.market_price`; ручные шаги кандидата (§6); затем сборка
   машинной книги, результаты книги, числа документов, прогулка версий, тесты книги.
3. **Объяснения гейтов** (`data/assumptions/gate_explanations.yaml`): новая запись `guidance_gap`
   (срок — не дальше следующего отчёта МСФО по календарю фактов), записи гейтов из таблицы
   «Проверки ядра на кандидате» — по массам нового прогона; записи гейтов, которые перестали
   срабатывать, снимаются.
4. **Проверка перед выкладкой:** `python -B data/assumptions/build_assumptions.py --check`,
   `python -B ops/tools/build_facts.py --check`, тесты книги, фактов и перезаякоривания, набор
   сервера на сегодня и «в будущем» (`FAKE_TODAY` + 1, + 7, + 30, + 60 дней), сборка выпуска —
   код 0. Скачок заголовка сторож выпуска пропускает по новой версии книги и новой дате фактов
   (М§14.4) — записка в `release_notes.yaml` не нужна.
5. Коммит, тег `book-<версия>`, выкладка через `main` (`docs/MANUAL.md` §10.7).

**Если к концу дня отчёта перенос не готов** — витрина не должна встать: новые записи объяснений
`guidance_gap` и `manual_input_overdue` (`docs/MANUAL.md` §10.4), перезаякоривание — на следующий
рабочий день.

### 1.7. Что записать

| Куда | Что |

## 3. Что переносится и как

Обозначения: A — прежняя книга; квартал 1 — её первый прогнозный, он же закрываемый; штрих —
величины новой книги. «На своём пути» — отчёт равен состоянию клетки на конец квартала 1.

### 3.1. Якорь, наблюдение, справочные ключи

`meta.anchor_period`, `first_period`, `facts_date`, `valuation_date`, `version` («<версия>+<квартал>»,
если не задана); `valuation.next_report.period` — новый первый прогнозный квартал.
`meta.last_period` не двигается.

**Наблюдение A-P2u** закрытого квартала — `{period, cor, nim, se 0, basis: mgmt, mu_cor, mu_nim}`:
упр. ЧПМ и CoR отчёта и ожидания режимов книги A на этот квартал (среднее слоя «свой взгляд» без
отклонений, М§12), переведённые в упр. базис мостом книги A. Нау-каст того же квартала заменяется
фактом; остаётся не больше `window_obs` последних наблюдений. Апостериорные вероятности в книгу не
вписываются, пути режимов под факт не правятся — факт считается один раз.

**Подмена наблюдения закрытого квартала** (`--observation <файл>`) — только решением книги или владельца
с записанной причиной, когда опубликованная упр. метрика квартала не годится наблюдением режима как есть
(разовая операция в ней, которую эмитент сам называет разовой). Файл — YAML или JSON: `cor`, `se_cor`,
`nim`, `se_nim` — значение и se каждой величины, доли единицы, все четыре обязательны (`null` — величина
не наблюдается, её se — `null` или 0); `reason` — причина, обязательна; `note` — подпись для витрины:
та же причина коротко, словами для владельца, одна строка не длиннее 80 знаков — обязательна, если
подмена меняет опубликованное число отчёта или не берёт его; `period` — необязательно (если задан —
квартал отчёта); незнакомый ключ, проценты вместо долей, se < 0, подмена числа без подписи — отказ до
расчёта. Запись наблюдения кандидата несёт **пометку подмены** (М§12): `published` — опубликованные
упр. числа подменённых величин, `reason` — подпись `note`; выпуск кладёт её в наблюдение, витрина
печатает рядом с подменённым числом («CoR 1,30 % (опубликовано 1,10 %) — причина»). Подмена одного se
при числе отчёта — не подмена числа: пометки и подписи не нужно.
Подменяется только наблюдение A-P2u кандидата на отчёте: факты — упр. метрики квартала, история моста,
журнал прогнозов (`record-actual`) — остаются опубликованными числами. Поправку несёт значение, а не
одна погрешность: сдвиг вероятности режима за одно наблюдение и так обрезан пределом
`joint.regime_update.max_shift_pp`, и умеренная se апдейт почти не ослабляет; se — неопределённость
самой поправки. Подмена видна в `REANCHOR.md` кандидата (шапка, «Производные величины», строка
наблюдения в «Что сдвинулось», строка «сюрприз факта»), копия с причиной — `observation.json`
каталога; в журнал версии она идёт строкой «суждения книги» (§1.7).

**Замороженные μ не пересчитываются** (решение ведущего; М§12). Запись окна хранит ожидания
режимов, действовавшие, когда квартал был открыт: инструмент пишет μ только новой записи и не
трогает прежние — ни при следующих переносах, ни при смене года якоря (§3.7). **Пол вероятности
режима** (`joint.regime_update.floor_share` × базовая) ядро применяет после каждого наблюдения —
одинаково в прежней книге с наблюдением и у кандидата; его действие целиком в строке «обучение»,
а `REANCHOR.md` кандидата называет режимы, стоящие на полу.

### 3.2. Цены якоря

Индекс цен клетки стартует с единицы на якоре, поэтому реальные суммы книги —
`noncore.result_real`, `other.misc_net_real` — и концы их осей умножаются на индекс цен закрытого
квартала I: из отчёта (`market.price_index`), иначе ожидаемый `Σ_W P_an(W) × (1 + cpi_W,1)^0,25`.

Сумма непрофильного результата года якоря закрывается остатком к факту (М§0.3), поэтому
индексируется только остаток года: `S' = F + (S − F) × I`, F — факт отчётных кварталов года в
книге A. Соседние годы, которые книга задаёт интерполяцией, при этом получают явные ключи (их
значения × I): правка ключа года якоря не должна сдвинуть их. Ось, которая двигает индексируемый
параметр вместе с другим, одним множителем не перевести — отказ.

При смене года якоря `noncore.price_base_year` — новый год якоря.

### 3.3. `anchor`-ключи

Отношения, которые клетка держит постоянными на всём пути (доля резерва, доля бумаг в ликвидных
активах, прочие активы и обязательства к кредитам, доли FVOCI и облигаций по СС, доля кредитов по
СС), остаются `anchor`: на новых фактах они воспроизводят себя сами.

Два правила опираются на состояние, которое идёт с лагом, и вывод заново сдвинул бы само правило —
они **замораживаются числами книги A**:

* линия доли текущих счетов `c*(key) = c_ref − ψ (key − key_ref)` — ключи
  `nii.retail_current_share.c_ref`, `key_ref` (доля якоря идёт к линии со скоростью ρ и на ней не
  лежит; факт доли — стартовое состояние клетки);
* базовое оптовое фондирование `volumes.wholesale_to_funds` (опт якоря включает добор до минимума
  ликвидности, М§4.10; базовое отношение — прежнее, добор клетка считает заново).

### 3.4. Капитал

* **Плотности RWA** — общим множителем `k = RWA отчёта / Σ плотность × остаток нового якоря`: индекс
  плотности стартует с единицы, и накопленный дрейф переходит в уровень. Валютная доля RWA (если
  переоценка включена) — `fx' = fx × Π / (1 − fx + fx × Π)`, `Π = I / (1 + π*)^0,25`: индекс курса
  тоже стартует с единицы.
* **Вычеты** `capital.n20.deductions_anchor`, `capital.n11.deductions_anchor` — формулами книги на
  новых фактах (М§4.11): BV − CET1 по Базелю; (BVreg − E) − базовый капитал банка.
* **Поправки** `capital.n20.gap_pp`, `capital.n11.gap_pp` — так, чтобы якорь модели воспроизводил
  Н20.0 и Н1.1 отчёта; ось поправки сдвигается вместе с центром.

### 3.5. Передача ставки: режим `keep`

Цели A-N2 (`nii.nim_lt_target_mgmt`), A-N3 (`nii.transmission.target`) и доли `nii.sigma0_split`,
`nii.phi_split` заданы на структуре якоря: ядро выводит из них **четыре скаляра пути** — сдвиги
спредов σ0_A и σ0_L, сжатие спредов кредитных книг φ_A и добавку к стоимости средств клиентов φ_L
(М§4.5). После квартала веса книг другие, и те же числа целей дали бы другие скаляры — сдвиг
спредов всего пути и терминала без единой новости. Поэтому при переносе якоря **скаляры
сохраняются**, а цели и доли пересчитываются на новую структуру:

```
цель A-N2'  = корень' + σ0_A / g' + σ0_L / h'        (σ0 аффинны по цели: g', h' — наклоны на новой структуре)
доля σ0'    = σ0_A / [g' × (цель A-N2' − корень')]
φ'          = φ_A + φ_L × L'/A'                      (объём сжатия: A', L' — веса книг с phi на новой структуре)
доля φ'     = φ_A / φ'
цель A-N3'  = та, при которой сжатие равно φ'         (φ аффинно по цели A-N3)
```

Решение — вызовами функции ядра `solve_transmission`, без её внутренностей (отношение A'/L'
читается из наклонов φ_L и φ по цели). Доля, стоящая на краю (0 или 1), остаётся на краю. Оси
суждений по целям пересчитываются тем же правилом: концу оси отвечают те же скаляры, что в книге
A. У оси доли это правило неприменимо (одно число доли задаёт два скаляра): она сдвигается вместе
с центром, конец оси на границе 0 или 1 остаётся на ней. Оси долей книги лежат в области гейта
`lt_spread_floor` (М§4.5): ось σ0 — от нуля до центра, ось φ — от центра до предела гейта; после
переноса они остаются такими же — у оси σ0 книги 1.3 на ожидаемом отчёте 3К26 0…0,09 переходит в
0…0,090093 (верхний конец — новый центр, эффективные спреды в нём прежние), ось φ 0…0,001 не
меняется. Пределы осей на новом якоре сверяют листы долей (§6).
Суждение — уровень и наклон ЧПМ сквозь цикл — не меняется: меняется его запись на новой
структуре баланса, и новые числа печатаются в «что сдвинулось».

Доли ω кредитных книг в разности опорных ставок X (на неё умножается φ_L, М§4.4) ядро берёт со
структуры нового якоря — скаляром они не сохраняются. Их сдвиг за квартал — доли процентного
пункта; эффект остаётся в строке «механика» и в её допуске (§5).

**`resolve` — только диагностика.** Цели, доли и их оси остаются числами книги A, скаляры ядро
решает заново; ближняя калибровка ЧПМ та же, что в `keep`, — сдвиг скаляров она не прячет, и он
целиком виден в строке «механика». Сдвиг заметный и сезонный: на якоре квартала ГОСА в пассивах
стоит объявленный невыплаченный дивиденд — беспроцентное фондирование, которого через квартал уже
нет. В этом режиме инструмент пишет только `REANCHOR.md` и ожидаемый отчёт.

### 3.6. Ставки якоря, ключи спредов, ближняя калибровка ЧПМ

**Ставки якоря несут весь ЧПД.** В отчёте процентный доход разложен по книгам, а модель держит
ближний сдвиг, сдвиг режима и отклонение A-P2u отдельным слагаемым Ov (М§4.4). Остаток
`ЧПД − (проценты активов − проценты пассивов − взносы АСВ)` — Ov ожидаемого отчёта, прочие
проценты настоящего — разносится по книгам активов пропорционально их процентному доходу:
`ставка якоря = проценты книги × (1 + остаток / проценты активов) / средний остаток × 365/d`.
То же правило — у сборщика фактов.

**Ключи спредов «от ставки якоря»** (М§4.4) выводятся заново у книг, которые следовали правилу в
книге A: ключ года первого прогнозного квартала — `ставка якоря − β × опора мира-эталона`; ключ
следующего года остаётся серединой до калибровки, если был ею.

**Ближняя калибровка** `regimes.near_nim_shift`. Уровень теперь внутри ставок якоря и уходит из
них со скоростью подстройки книг; прежний ближний сдвиг посчитал бы его второй раз. Калибровка
выводится на **ожидаемом отчёте**: по прогону кандидата

```
near'(q) = near(q) − [ЧПМ'(q) − ЧПМ_A(q)]        (ожидание слоя «свой взгляд»; повторять до сходимости)
```

пока ожидаемый путь ЧПМ кандидата не совпадёт с путём книги A с тем же наблюдением. Траектория
книги: квартальные ключи — по год после якоря (и дальше, пока значения внутри года расходятся
больше чем на 0,02 п.п.), затем ключи лет со средним года, пока хвост больше 0,0001 п.п., `LT` —
прежний. Ключ последнего года сетки — не уровень, а погашение остатка уровня в ставках: терминал
читает тот же ЧПМ, что в книге A. К фактическому отчёту применяется калибровка, выведенная на
ожидаемом: отличие его ставок от ожидаемых остаётся в ставках книг и затухает их лагами — это
сюрприз факта.

### 3.7. Смена года якоря

Год шока кризиса — год якоря + `shock_year_offset` (М§3.2): сдвиг сохраняется, а ключи-годы и
ключи-кварталы кризисных траекторий (`cor`, `nim_shift`, `loan_growth_adj`, `loan_growth_override`),
период разового убытка, годы `checks.m_crisis_vs_cbr.loan_growth` и пути осей по этим ключам
сдвигаются на год. `nii.sigma0_from` — не раньше года первого прогнозного квартала. Концы прошлого
года для гайденса (`prev_year_end`) — остатки прежнего якоря.

Режим «перезаряжается»: кризис снова впереди, хотя ожидаемый отчёт уже нёс его долю. На смене
года строки «механика» и «выпуклость» ненулевые по определению стационарных режимов: клетки
перезаряженного режима в допуск механики не входят (прочие — входят), инструмент называет это
предупреждением.

**Замороженные μ при смене года** — по общему правилу §3.1: не пересчитываются. Наблюдение
закрытого квартала (первого квартала нового года) судится против ожидания книги A — с шоком:
несостоявшийся шок остаётся свидетельством против кризиса и переходит в перезаряженный режим
затухающим отклонением, пока запись не выйдет из окна (четыре отчёта). Снизу эффект ограничен
полом вероятности режима. Следствие — заранее известный сдвиг точки на ожидаемом отчёте раз в
год: его показывает сухой прогон (строки «обучение», «механика», «выпуклость»), и он записывается
в журнал версии книги. Гайденс нового года (`volumes.guidance_year`, `guidance_growth`,
`fees.growth_override`) — решение книги: без него новый год растёт по общему правилу, как рос в
книге A.

**Почему правило оставлено** (сравнение трёх правил на книге 1.3, цепочка восьми отчётов 3К26…2К28

|---|---|---|---|---|
| 3К26 | −3,3 / −3,0 | −3,3 / −3,0 | −3,3 / −3,0 | −0,5 / −0,2 |

| 2К27 | +21,6 / +20,7 | −8,8 / −9,7 | −12,5 / −13,3 | +2,8 / +2,0 |

у замороженных μ и −22,1, −1,6 при сбросе). Качели ±22 ₽ первой колонки — свойство ожидаемого отчёта
в квартале шока (среднее двугорбого прогноза, CoR 2,1–2,5 % при 1,5 % без шока и 5 % с шоком), а не
правила: на отчётах без шока наибольшая строка «обучение» — 8,1 ₽. Цена замороженных μ после отчёта

### 3.8. Факты кандидата

Рабочие факты нового якоря (`facts/*.json` каталога) — те же файлы с узлами якоря из отчёта
(`calc: reanchor…`): остатки книг разложены по строкам баланса в долях прежнего якоря; квартал
добавлен в историю ОПУ, баланса и капитала (в историю баланса — и конец прежнего якоря, если его
там не было); **упр. факты квартала входят в историю моста упр. ↔ МСФО** — год якоря в упр.
базисе ядро собирает из отчётных кварталов (М§4.6: гейт гайденса, годовые упр. метрики выпуска);
среднее моста продлевается закрытым кварталом; узлы, которых отчёт не называет, — `null`. Ядро
читает из них то же состояние якоря, что из канона сборщика (`--compare-facts`; тест
`tests/test_facts_expected.py`).

## 4. Разложение скачка

Все строки — на одной дате оценки, точка при значениях книги; с `--band` — ещё медиана и полоса
80 % на одних точках гиперкуба.

| Строка | Разность | Смысл |
|---|---|---|
| обучение | A⁺ − A | A⁺ — книга A с наблюдением, равным ожиданию модели: при смеси режимов не ноль (М§12); сюда же — предел сдвига, пол вероятности режима и наблюдение, выпавшее из окна |
| **механика** | O − A⁺ | каждая клетка перезаякорена на своём пути, вероятности — как в A⁺. **≈ 0** |
| выпуклость | E − O | кандидат на ожидаемом отчёте: один отчёт на все клетки (неравенство Йенсена) |
| сюрприз факта | F − E | кандидат на отчёте с той же ближней калибровкой ЧПМ; при подмене наблюдения (§3.1) — и с ней: прочие строки подмены не видят |

**Квартал шока.** Если закрываемый квартал лежит в году шока книги A (отчёт за первый квартал
года), под таблицей печатается абзац «Квартал шока режима …»: CoR ожидаемого отчёта, вероятность и
CoR шока в нём, наблюдение отчёта без шока (ожидание прочих режимов с их вероятностями, в сумме 1),
строка «обучение» на нём и вероятности режимов после него (§3.7).

**Допуск механики** — стоимость каждой клетки на своём пути в пределах 0,1 % (М§15.2); нарушение
— код 1: какое-то правило, помнящее прошлое, не перенесено. Строка считается по всем клеткам
(`--no-cells` — пропустить; тогда механика и выпуклость — одной строкой, допуск не проверяется).
На смене года якоря клетки перезаряженного режима в допуск не входят (§3.7).

**Медиана.** Клетки на своём пути в полосе не пересчитываются, поэтому у медианы механика и
выпуклость — одной строкой E − A⁺. Она мала, но не ноль по построению: отчёт один на все розыгрыши
полосы, и закрытый квартал перестаёт разыгрываться. Оси с несимметричным диапазоном, часть эффекта
которых приходилась на него (реальный рост расходов года якоря, дрейф плотности RWA, сдвиг
налоговой ставки), сдвигают медиану к значению книги: отчёт «по центру» для таких осей — хорошая
новость. Тест держит строку в половине шага печати.

**Проверки ядра на кандидате.** `REANCHOR.md` печатает нарушенные инварианты и сработавшие гейты
кандидата рядом с гейтами прежней книги на той же дате оценки (М§14.1–§14.2): видно, какие гейты
появляются и уходят с новым якорем. Отказ ядра (нет факта, без которого проверка не считается)
печатается причиной.

## 5. Свойства, которые перенос не закрывает

* **Доли ω в разности опорных ставок.** Добавка к стоимости средств клиентов — `φ_L × X`, X —
  разность опорных ставок кредитных книг мира и мира-эталона, взвешенная их долями на якоре
  (М§4.4). Доли берутся со структуры нового якоря и за квартал сдвигаются на доли процентного
  пункта; при сохранённом φ_L это меняет добавку в мирах, далёких от эталона. Эффект — в строке
  «механика», на порядок меньше допуска; `REANCHOR.md` печатает сдвиг долей.
* **κ-добавка закрытого квартала.** Добавка к CoR от реальной ставки с лагом L кварталов: для
  кварталов до сетки ядро считает её нулём (М§4.6). Если в закрытом квартале реальная ставка мира
  выше, чем в мире N, добавка квартала L + 1 теряется при переносе якоря; инструмент называет
  величину предупреждением, эффект — в строке «механика».
* **Два определения ЧПМ движка.** Клетка считает ЧПМ на среднем остатке с предварительным концом
  квартала (М§4.10), факты и мост — на среднем отчётных остатков; разница — около 0,02 п.п. На
  ожидаемом отчёте мост ЧПМ поэтому сдвигается на тысячные доли п.п. (строка «выпуклость»).
* **Замороженные μ в полосе.** В книге A розыгрыш, меняющий ЧПМ закрытого квартала, гасится
  наблюдением (ожидания режимов пересчитываются в прогоне); в новой книге μ заморожены на
  значениях книги. Полоса кандидата по таким осям чуть шире.
* **Окно первых кварталов.** Гейты, которые смотрят на первые кварталы пути от якоря
  (`nim_path_joint`), после переноса видят окно, сдвинутое на квартал, и новый ЧПМ якоря: гейт
  может сработать на кандидате при отчёте без новостей. Это видно в сухом прогоне (§1.1) и
  требует объяснения, а не правки переноса.
* **Суждения.** LT-уровни, диапазоны осей, вероятности, миры инструмент не трогает; их пересмотр
  — решение книги той же версии.

## 6. Ручные шаги после кандидата

Инструмент печатает их в `REANCHOR.md`: правила центров `nii.sigma0_split` и `nii.phi_split` и
неподвижная точка дисконта за управление на новом якоре (листы обоснований книги); миры и кривые
(отдельной версией книги с семейством); `meta.market_price`, `meta.date`; сетки «что даст отчёт»;
гайденс нового года; ширина осей поправок нормативов; объяснения гейтов, результаты книги и
закреплённые числа. Каждое такое решение — строка «суждения книги» в журнале версии, отдельно от
строк разложения.

фикстуры, не от «сегодня». Быстрые (`tact`): клетки трёх миров на своём пути сохраняют стоимость;

смену года якоря (в квартале шока сухой прогон печатает строку отчёта без шока, в прочих — нет);
запуск из командной строки; настоящая книга.
