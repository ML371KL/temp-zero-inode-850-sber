# Факты Сбербанка: схема файлов `data/facts/*.json`

Факты — отчётные числа на дату якоря и история до неё. Ядро (`model/book.py::load_facts`) читает их
как есть; сборка выпуска и витрина — через ядро или `model/payload.py`. Методика — `docs/MODEL.md`
(прил. B — поля, которые читает ядро), происхождение каждого числа — `docs/FACTS.md`, сборщик —
`ops/tools/build_facts.py` (листы этапа 1 из `$BANK_HANDOFF_DIR`; якорь — аргумент `--anchor`; в CI не
запускается — JSON закоммичены), тесты — `tests/test_facts_*.py`. Что привязано к якорю и как перейти
на следующий квартал — §3; факты «ожидаемого отчёта» для сухого прогона перезаякоривания — §4; лист
квартала (что внести из нового отчёта и откуда) — §5.

## 1. Общие правила

**Узел.** Каждое число — узел, голых чисел нет:

```json
{"v": 8387.2, "calc": "equity.total − at1 − nci = 8531,8 − 150,0 − (−5,4)"}
{"v": 16266.3, "src": "2026H1_ifrs_interim_statements.pdf, с. 16, sha256 5b3a3de88ae6c96b"}
{"v": 359.8, "src": "ifrs_FY2024_statements.pdf, с. 7, sha256 fbd4d739ce58c597; ifrs_9M2024_statements.pdf, с. 6, sha256 75c4a0d7f4932954", "calc": "FY2023 − 9M2023 (разность нарастающих итогов)"}
{"v": null, "calc": "не раскрыто: обратное репо отдельно не раскрыто — внутри средств в банках"}
```

* `v` — число (`int`/`float`), `null` или, только в `guidance.json`, диапазон `[мин, макс]`.
* `src` — документ(ы): `имя файла, с. N` (или лист папки передачи и что в нём взято), `sha256` — первые 16
  знаков хэша документа; несколько документов — через `; `. Полный sha256, путь в папке передачи
  и адрес каждого документа — реестр `anchor.json → documents` (тест: каждый префикс в `src`
  находит ровно один документ реестра).
* `calc` — формула из других узлов (имена полей, числа) или пересчёт единиц (% → доли, тыс. ₽ →
  млрд ₽, смена знака); у `null` — причина: «не раскрыто: …» (документ числа не даёт) или «нет
  данных …» (данные есть, но величина из них не строится — почему, с числами).
* Узел с числом обязан иметь `src` или `calc` (с буквой или цифрой); `null` — обязан иметь `calc`.
* Дополнительные поля узла допустимы: `basis`, `as_of` (узлы смешанного `capital.json`), `kind`, `text`,
  `date`, `event`, `scope`, `relation`, `scope_note`, `tol` (гайденс; `tol` — единственное число внутри
  узла помимо `v`).
* Число, которого на странице документа нет, а есть значение сравнимого периода и изменение к нему,
  несёт вывод в `calc`: «выведено: 26,9 + 1,4 = 28,3 — …». Если число напечатано в другом документе,
  `src` указывает на него, а вывод остаётся сверкой: «напечатано на странице; сверка — …».
* Коды и перечни — строками (`"45.0"`, `"501"`), не числами.

**Голые значения вне узла** допустимы только:
* строки (даты `YYYY-MM-DD`, периоды `2026Q2`, названия, пояснения `note`, `basis`, `unit`, `sign`,
  `calc`-подобные тексты в полях `definition`, `direction`, `text`);
* булевы флаги (`pre_dividend`);
* годы: ключ `year` и `dividends_payable_year`;
* `null` у дат, которых нет (`record_date` года без выплаты).

**Строки, которые печатает витрина** (`docs/PAYLOAD.md` §0.2): названия и записки событий календаря
(`title`, `note`), записка о прогнозе сектора и события пересмотров гайденса (`scope_note`, `event`), текст и
записка о сроке дивидендной политики (`text`, `valid_until_note`), база сравнения и подписи аналогов (`basis`,
`name`, `capital_ratio.name`). Они — словами для владельца: без кортежей и имён полей ответов источников, без
меток класса допущения («оценка», «факт» — словом), без хвостов sha256 и путей к листам, без рабочих пометок;
дата — с годом («к 29.04.2026»: короткая дата читается на экране как дробь), период — словами, а не кодом.
Правится сама строка факта, а не маска на витрине; запреты держит `tests/test_facts_texts.py`. Происхождение
(документ, страница, sha256) живёт в `src`, а не в записке.

**Единицы.** Деньги — млрд ₽; акции — млн шт.; ставки, доли, коэффициенты, нормативы, CoR, ЧПМ —
доли единицы (проценты документов делятся на 100); DPS — ₽ на акцию.

**Знаки.** ОПУ (`pnl_quarterly`) — как в отчётности: расходы, резервы, налог, взносы АСВ — со знаком
минус; тождество `pbt = nii + llp_debt_fa + fees_net + insurance_net + noncore_net + opex + misc_net`
(MODEL §4.7). Остатки баланса — величинами (резерв `allowance_ac` — положительный, в активах
вычитается); компоненты капитала (`treasury_cost`, `fvoci_reserve`, `other_reserves`, `nci`) — со
знаком отчёта. Купон AT1, дивиденды к выплате, взносы АСВ в `nii_books` — величинами (так сказано в
`calc`).

**Базис.** Каждый файл несёт `basis`: `IFRS` (МСФО группы), `RAS` (РСБУ банка соло), `mgmt`
(управленческие метрики презентаций), мосты — `mgmt↔IFRS`, `RAS→IFRS`; `capital.json` — `mixed`,
и тогда у каждого блока свой `basis`. Базисы в одном поле не смешиваются; упр. ↔ движок — только
через `bridge_mgmt_ifrs.json` (MODEL §4.6). `calendar.json` чисел не несёт и `basis` не имеет.

**Периоды и даты.** Кварталы — `2026Q2`; даты — `YYYY-MM-DD` (календарные, МСК); `as_of` файла —
дата якоря (кроме `calendar.json`, `peers.json` — дата сбора).

**Нераскрытое — `null`, не 0.** Ноль — только там, где он раскрыт или следует из правила
(купон AT1 вне декабря — `calc` говорит об этом).

## 2. Файлы (что читает ядро — жирным)

### `anchor.json` (IFRS)
**`as_of`** (2026-06-30), **`period`** (2026Q2), `note`, `documents` [] — реестр документов:
`{key, file (путь в папке передачи или null — файл не сохранён), sha256 (полный), url, title}`; `title` печатает витрина как источник числа —
название документа словами для владельца (дата — с годом, без имён файлов и рабочих пометок).

### `balance.json` (IFRS, на `as_of`)
* **`loans_ac_gross.{commercial, project, mortgage_market, mortgage_subsidized, consumer, cards,
  auto}`**, `mortgage` (итог), `total`; **`loans_fvtpl`**; **`allowance_ac`** (величина).
* **`securities.{fvoci_debt, fvoci_repo, ac, ac_repo, fvtpl_bonds}`**, `fvtpl_equity`,
  `fvoci_equity` (акции и фонды — вне книги `securities`, в `other_assets`), `debt_total`.
* **`liquidity.{cash, cbr, due_from_banks, reverse_repo}`** (`reverse_repo` — null), `total`.
* **`other_assets`** (calc: активы − перечисленное), `total_assets`.
* **`funds.{retail_current, retail_term, corp_current, corp_term}`** (ЮЛ — с госорганизациями;
  репо клиентов — в срочных).
* **`wholesale.{banks, issued_debt, subordinated, repo_cbr}`** (`repo_cbr` — null).
* **`other_liabilities`** (без дивидендов к выплате), **`dividends_payable`**, `dividends_payable_year`,
  `total_liabilities`.
* **`equity.{total, at1, nci, bv_common}`**, `equity.{shareholders, share_capital, share_premium,
  treasury_cost, fvoci_reserve, other_reserves, retained_earnings}`.
* **`prev_year_end.{loans_corporate, loans_retail}`** (+ `as_of`) — база гайденса роста (MODEL §4.3):
  тот же состав, что сегменты книг (корп. = коммерческие + проектные + по СС; розн. = ипотека +
  потреб + карты + авто).
* `iea` (calc) — процентные активы движка на якоре.
* **`history`** — словарь «период → конец квартала» {`2022Q4` … `2026Q2`}: `{date, loans_ac_gross,
  allowance_ac, loans_fvtpl, equity_shareholders, bv_common, total_assets, iea}` (узлы). Читает ядро:
  концы до якоря для годовых отношений года якоря (MODEL §0.3), история выпуска, мосты ЧПМ и процентных
  активов; `iea` на даты 2023–2024 — оценка по обобщённой форме (помечено в `calc`).
Тождество (тест): Σ кредитов АС + по СС − резерв + долговые бумаги + ликвидность + OA = total_assets
= funds + wholesale + OL + DP + equity.total.

### `nii_books.json` (IFRS; квартал якоря)
`period`, `days` (узел), `unit`; `books.<b>` для 10 книг схемы (`corp_loans`, `mortgage`,
`mortgage_sub`, `retail_loans`, `securities`, `liquidity`, `retail_current`, `retail_term`,
`corp_funds`, `wholesale`): `balance_open` (конец прошлого квартала), `balance_close` (= balance.json),
`balance_avg`, `interest_q` (проценты квартала; для кредитных книг — разбиение calib-nii, calc),
**`rate_anchor`** (доля, act/365). Плюс `interest_loans_q`, `other_interest_net_q` (вне книг),
**`dia_q`** (взносы АСВ, величиной), `dia_rate`, `nii_q`, `iea_avg`, `nim_eng_q`,
**`current_share_anchor`**, **`key_avg_anchor_q`**. Сверка: Σ книг + прочие − АСВ = ЧПД отчёта.

`rates_carry_residual` (флаг) — правило ставки якоря. `false` (якорь 2026Q2): `rate_anchor` = `interest_q`
/ `balance_avg` × 365/d, процентный доход вне книг — только в `other_interest_net_q`. `true` (якоря,
полученные перезаякориванием, с `RATES_CARRY_FROM`; MODEL §15.2 п. 4): ставки книг активов несут весь
ЧПД — `rate_anchor` = `interest_q` × (1 + остаток / Σ процентов активных книг) / `balance_avg` × 365/d,
где остаток = `nii_q` − (Σ процентов активных книг − Σ пассивных − `dia_q`); `interest_q` и
`other_interest_net_q` остаются как в отчёте. То же правило — в `ops/tools/reanchor.py`.

### `pnl_quarterly.json` (IFRS; `quarters.<2023Q1…2026Q2>`)
**`nii`**, **`fees_net`** (+ `fee_income`, `fee_expense`), **`llp_debt_fa`** (числитель CoR движка),
`fv_loans_credit` (null), **`insurance_net`** (выручка + расходы на услуги), `insurance_finance`,
`misc_net` (calc: остаток до PBT), `fvtpl_bond_reval` (null), **`noncore_net`**, **`opex`**,
**`pbt`**, **`tax`**, **`ni`**, **`ni_shareholders`**, `ni_nci`, `dia`, `oci_fvoci`, `oci_total`,
`ci_shareholders`, `other_equity_movements`, `at1_coupon` (величиной: 0 вне квартала выплаты, в квартале
выплаты — купон года, «год − 9 месяцев»; Σ кварталов = `dividends.history[].at1_coupon`), **`key_avg`** (средняя ключевая квартала по
календарным дням, доля; флаг `ni_jump`, MODEL §14.3; `null` — квартал флагом не проверяется). Кварталы
2023 года — обобщённая форма: страхование, непрофильная деятельность и остаток — `null` (свёрнуты в
прочие). Квартал, полученный разностью нарастающих итогов, помечен в `calc`.

Доли кварталов «прочего» (ключ книги `other.misc_quarter_shares`, MODEL §4.7) считает книга из
`misc_net` полных лет (`evidence/bridges`); в фактах их нет — у числа один дом.

### `capital.json` (mixed)
**`at1.{amount, coupon_annual, coupon_quarter}`** (IFRS); **`t2_recognized`** (прокси — T2 по
Базелю); **`basel.{cet1_ratio, cet1, t1_ratio, t1, t2, total_ratio, total_capital, rwa}`**;
**`n20_0.{value, as_of, pre_dividend}`**, `n20_0.min_with_buffers`; **`n1_1_bank.{value, as_of}`**
(RAS, форма 0409135 — прокси Н20.1), `n1_1_bank.ifrs_note_value`; `n1_0_bank`, `n1_2_bank` (узлы с
`basis`, `as_of`); **`bank_base_capital`** (узел: базовый капитал банка, форма 0409123, код 102 — для
Ded11_0), `bank_own_funds` (узел, код 000); **`fvoci_reserve`**;
**`ofz_curve_anchor.{1, 3, 5, 10}`** (+ `as_of`, `convention`); `history` [] по кварталам
2022Q4–2026Q2: `{period, date, n20_0, cet1_ratio, t1_ratio, total_ratio, cet1, rwa, n1_1_bank}`.

### `shares.json` (IFRS)
**`issued_ordinary`**, **`issued_preferred`**, **`issued_total`** (N_iss), `treasury_ordinary`,
`treasury_preferred`, `treasury_prev_year_end`, **`outstanding_ordinary`**,
**`outstanding_preferred`**, **`outstanding_total`** (N_out), `par_value`, `by_ticker`.

### `dividends.json` (IFRS)
* `policy`: `name`, `doc`, `sha256`, `approved`, `approved_by`, `valid_until` — срок действия по
  документу: дата утверждения + срок политики (п. 6.4 Положения — 3 года); считается сборщиком, литералом
  не вписывается; `valid_until_src` (страница с пунктом о сроке; при продлении — и сообщение о нём),
  `valid_until_note` (печатается на витрине: срок, пункт документа и что будет после срока — словами, дата с
  годом), `base`, `payout` (узел), `threshold` (узел), `divisor`, `divisor_src`, `text`, `src`.
  **Истёкший срок выпуск не блокирует** (MODEL §5.1, §14.3): после `valid_until`, пока новой политики нет,
  клетки платят по прежней, а выпуск несёт флаг `policy_expired`; теста «срок не раньше сегодня» нет. Новая
  политика или продление срока — §3.
* **`history`** [] (годы прибыли 2023–2025): `year`, `dps_ordinary`, `dps_preferred` (узлы, ₽),
  `record_date`, `last_buy_date`, `ex_date`, `pay_date`, `settlement` (T+1 / T+2), `pool_declared`,
  **`ni_shareholders`**, **`at1_coupon`**, **`tax_statutory`**; `decided_date` (дата решения годового
  собрания), `sources` [] — источники записи (формат ниже: документ эмитента и новость о решении ГОСА).
* `history_before` [] (годы 2013–2022; витрина): `year`, `dps_ordinary`, `dps_preferred`, даты,
  `decided_date`; год без выплаты — DPS 0 с решением собрания в `calc`, даты — `null`.
* **Дивиденды — публичные факты.** Размер на акцию каждой категории, дата отсечки и дата решения — из
  решений годовых собраний акционеров: лист `stage1/market/shares_dividends/dividends_public.csv` (документ
  реестра `dividends_public`) с источником каждого года — страница «Дивиденды» на сайте банка (история выплат:
  год, дивиденд на акцию, дата определения списка лиц, общий размер) и новость о решении собрания (издание,
  дата, заголовок, адрес). Общий размер выплаты страницы эмитента сборщик сверяет с объявленным в отчётности
  МСФО. Остальные даты — по правилу от отсечки (`dates_rule` — правило словами): `settlement` — T+2 до
  28.07.2023, затем T+1; `ex_date` — день отсечки при T+1, торговый день перед ней при T+2;
  `last_buy_date` — торговый день перед экс-датой; `pay_date` — **срок выплаты** номинальным держателям,
  10-й рабочий день после отсечки (п. 6 ст. 42 закона об акционерных обществах; тот же срок называет страница
  эмитента), а не день зачисления у конкретного брокера. **Брокерский календарь** (T-Invest) в факты не идёт:
  сборщик сверяет с его снимком в папке передачи размер, отсечку, экс-дату и последний день покупки и пишет
  итог словами в `broker_check`; расхождение — отказ сборки. Выписок ответов брокерского API и имён их полей
  в фактах нет.
* `register_seed` [] — объявленные и не выплаченные на дату книги (записи — поля
  `model.grid.DividendRecord`: `year`, `dps` (узел), `status` (`declared` | `recommended` | `paid`),
  `record_date`, `last_buy_date`, `ex_date` (= отсечке, T+1), `pay_date`, `decided_date`, `sources`);
  сейчас пуст, причина — `register_seed_note`.
* **Запись реестра — два источника** (MODEL §15, решение B3). `sources` — список строк
  «`<вид>: <что и откуда>, sha256 <префикс>`», вид ∈ {`tinvest` — брокерский календарь дивидендов (живой
  реестр выпуска: размер и дата отсечки); `news` — новость Интерфакса или ТАСС о решении ГОСА (для
  `recommended` — о рекомендации совета директоров): размер, отсечка, дата решения; `manual` — ручная запись
  по документу эмитента (в живом реестре — команда оператора `record-dividend`, запасной второй источник)}.
  У `declared` — не меньше двух источников **разных видов** (два снимка брокерского календаря — один
  источник); отсечка — через 10–20 дней после `decided_date`. В фактах история несёт виды `manual`
  (страница «Дивиденды» эмитента) и `news` (новость о решении); пример — `history[]` за 2025 г. (страница
  эмитента + Интерфакс 30.06.2026, копия новости — в папке передачи: дата решения, размер и дата реестра
  сверены с её текстом); тест — `tests/test_facts_register.py`.
Тест: `ceil_kopeck(0,5 × (ni_shareholders − at1_coupon × (1 − tax_statutory)) × 1000 / N_iss)` =
`dps_ordinary` за 2023–2025 в `Decimal` (MODEL §5.2, прил. C).

### `bridge_mgmt_ifrs.json` (mgmt↔IFRS)
**`window`** [с, по]; `direction`; для x ∈ {cor, nim, cir}: **`x.{method, value}`**, `x.{sd, n,
definition, history}`. `history` []: `{period, mgmt, engine, gap}` (узлы; `gap = engine − mgmt`);
`value` — среднее `gap` по окну. `to_engine(v) = v + value`. CIR движка = −opex / (nii + fees_net +
insurance_net + misc_net) квартала (MODEL §4.6); кварталы 2023 года — `null` (обобщённая форма);
`cir.annual.<год>` — `{mgmt, engine, gap}` суммами года (справочно; гайденс CIR — годовой). Мост CIR
служит гайденсу и печати, не гейту `bridge_drift`.

### `bridge_ras_ifrs.json` (RAS→IFRS; читает `indicators/nowcast.py`, не ядро)
ЧП (T1): `quarters` []: `{period, ras_ni, ifrs_ni_sh, ratio, src}`; `by_quarter.{"1","2","3","4"}` —
среднее отношение по номеру квартала; `annual.<год>`.

ЧПД (T3) — `nii`, процентные активы — `iea` (одна форма): `definition`, `method`, `window` [с, по]
(последние N кварталов до якоря), `quarters` [] `{period, ras, ifrs, ratio, src}` (ratio = ifrs / ras),
**`value`** (среднее ratio по окну), `n`, `sd` (при n > 1), **`by_quarter.{"1".."4"}`** (= `value`:
сезонность не подтверждена бэктестом), `backtest.{prev_quarter, mean_4, same_quarter}` (RMSE прогноза
отношения квартала). `nii.ras` — ЧПД банка из месячных релизов РСБУ (кварталы 2–4 — разность
нарастающих итогов), `nii.ifrs` = `pnl_quarterly.nii`. `iea.ras` — средние процентные активы банка по
форме 0409101 (среднее концов квартала: формы на 1-е число первого месяца квартала и месяца после
него), `iea.ifrs` — среднее `balance.history.iea` концов квартала; состав РСБУ — `iea.codes`
(`loans`, `interbank`, `securities` — коды строками; «45.0|45.1» — первый найденный), `codes_required`,
`codes_note`, `basis: "engine"` (сторона МСФО — процентные активы движка, поэтому ЧПМ по мостам — в базисе
движка; в упр. — мостом `bridge_mgmt_ifrs.nim`). ЧПМ движка по РСБУ = ЧПД РСБУ × `nii.value` × 365/d / (активы РСБУ × `iea.value`).

CoR (T4) — `cor`: блок той же формы (РСБУ → упр.) или узел `{"v": null, "calc": "нет данных …"}`
(сейчас — узел: разброс разности CoR РСБУ и упр. не меньше разброса самого упр. CoR); тогда нау-каст
CoR равен ожиданию модели.

### `mgmt_quarterly.json` (mgmt)
`quarters.<2019Q1…2026Q2>`: `nim`, `cor`, `cor_corporate`, `cor_retail`, `cir`, `roe`,
`cost_of_funding`, `asset_yield`, `cost_retail_funds`, `cost_corp_funds`, `n20_0`, `loans_corporate`,
`loans_retail`, `loans_mgmt`, `provisions_credit`; `annual.<год>`: `nim`, `cor`, `cir`, `roe`.
Квартальных презентаций 4К21–4К22 нет — `null`.

### `guidance.json` (mgmt)
**`year`**, **`as_of`**, **`items.{roe, nim, cor_max, cir, fee_growth, n20_0,
loan_growth.corporate, loan_growth.retail}`** — узлы: `v` — число или `[мин, макс]`, **`kind`** ∈
{`point`, `min`, `max`, `range`} (`n20_0` — `min`: «>13,3 %» — пол политики, не точка; `cor_max` —
`max`), `text` (как в презентации), `date`, `event`; **`tol`** — только у `point`: половина единицы
последнего разряда числа, как оно записано в `text` («22%» → 0,005; «~6.2%» → 0,0005; «~0%» → 0,005);
**`scope`** ∈ {`group`, `sector`}: `group` — цель банка, `sector` — прогноз сектора, а не банка (рост
кредитов); у `sector` — **`relation`** ∈ {`in_line` — «в соответствии с сектором», `above` — «лучше
сектора»} и `scope_note` (слова презентации; сборщик сверяет с ними `relation`; печатается на витрине,
поэтому короткую дату записки листа сборщик дополняет годом из дат гайденса: «к 29.04» → «к 29.04.2026», даты с
таким днём и месяцем нет — отказ). Гейт `guidance_gap` узлы `sector` не берёт (MODEL §14.2).
Все величины — упр. базис (CIR — через `bridge_mgmt_ifrs.cir`). `history` []: `{date, key, value (узел), event, note}` — исходный гайденс
и пересмотры.

### `calendar.json` (ведётся вручную; сборщик не пишет)
`{"as_of", "horizon", "note", "sources": [{key, title, url, accessed, file, sha256, note?}], "events": [{"id",
"kind", "date", "title", "covers", "confirmed", "precision", "earliest"?, "latest"?, "src", "note"?}]}` —
события не меньше 12 месяцев от `as_of`, по порядку дат; `src` ссылается на `sources` префиксом sha256.
Источник без адреса и файла (`url`, `file` — `null`) — снимок календаря отчётов эмитента у брокера: в
репозитории — только название словами и sha256 снимка из папки передачи, сам ответ и его поля не публикуются.
`kind` ∈ {`ifrs`, `ras`, `cbr_rate`, `cbr_forecast`, `agm`, `record`, `investor_day`}; `covers` —
период отчёта (`2026Q3` у МСФО, `2026M09` у РСБУ) или `null`; `precision` — `day` | `window`
(у окна — `earliest ≤ date ≤ latest`); `confirmed: false` — оценка по прецеденту (прецедент — в
`note`: только даты не позже `as_of`; объявленная, но не наступившая дата прецедентом не называется и
пишется отдельно, с источником); `id` уникален. Заседание ЦБ с опубликованием среднесрочного прогноза — `cbr_forecast`,
прочие — `cbr_rate`. `title` и `note` печатает витрина (на неделе события — и баннер): словами, по правилам §1;
откуда дата — в `src`, а в записке — человеческим языком («дата из календаря эмитента в T-Invest»).

### `peers.json` (ведётся вручную; читает сборка выпуска, не ядро)
`{"as_of", "basis", "subject_ticker", "note", "sources": [{key, title, url, accessed, file, sha256}],
"banks": [{"ticker", "name", "basis", "bv_date", "ni_ltm_period", "bv", "bv_prev", "ni_ltm",
"roe_ltm", "shares_outstanding", "shares_issued", "dps_ltm", "capital_ratio": {"name", "value",
"as_of"}, "src"}]}` — `basis` верхнего уровня печатается на витрине как есть: словами, по столбцам
таблицы аналогов, без имён полей; числа (`bv` — капитал обыкновенных акционеров, `bv_prev` — год назад, `ni_ltm`,
`roe_ltm` = ni_ltm / среднее bv, `shares_outstanding`, `shares_issued`, `dps_ltm` — DPS с датой
реестра за 12 месяцев, `capital_ratio.value`) — узлы `{v, src|calc}`; `src` ссылается на `sources`;
нераскрытое — `null` с причиной. Строки эмитента нет (её строит выпуск из фактов Сбера); цен нет
(живой вход сборщиков).

## 3. Как обновлять: якорь и что к нему привязано

**Якорь — аргумент сборщика.** `python -B ops/tools/build_facts.py [--check] [--anchor <период>] [--out
<каталог>]`; без `--anchor` — квартал `anchor.json`. Литералов квартала в коде сборщика нет (тест
`tests/test_facts_anchor.py`): всё, что зависит от якоря, выводится из него и из листов.

**Выводится из якоря само** (класс `Anchor` и данные листов; править нечего):

| Что | Правило |
|---|---|
| дата якоря, начало квартала, дата форм ЦБ | конец квартала; конец прошлого квартала; 1-е число после квартала |
| лист якоря | тот `stage1/ifrs/ifrs_anchor_*.csv`, чей отчётный период кончается датой якоря; якорь на годовом отчёте листа не требует |
| нарастающий итог (`6M2026`), последний годовой отчёт (`FY2025`), конец прошлого года | из номера квартала и года |
| ряды `pnl_quarterly`, `mgmt_quarterly`, `balance.history`, `capital.history`, мосты | от начала ряда до якоря |
| окно моста упр. ↔ МСФО | от `BRIDGE_FIRST` до якоря (растёт на квартал) |
| последний объявленный дивиденд | последний год с раскрытыми в МСФО объявленными дивидендами и решением собрания (лист решений) не позже якоря |
| `balance.dividends_payable` | срок выплаты после якоря — сумма к выплате; иначе 0 |
| `capital.n20_0.pre_dividend` | месяц отсечки после якоря — `true` (норматив до вычета) |
| годы теста DPS | от `DIV_FIRST_YEAR` до года последнего объявленного дивиденда |
| собственные акции | из дивиденда последнего решения на собственные акции и его DPS |
| год гайденса | год якоря |
| срок политики | `POLICY_APPROVED` + `POLICY_TERM_YEARS` |
| тексты `calc` («на 31.03.2026», «2К», «6М26») | из дат якоря |

**Порядок.**
1. Новый отчёт МСФО → первичка и листы этапа 1 (таблица выше; строки отчёта и презентации — инструментами
   этапа 1 или листом квартала, §5) → `python -B ops/tools/build_facts.py
   --anchor <период> --out <каталог> --report <отчёт.json>`: сверки сходятся — кандидат фактов и файл
   отчёта квартала (`quarter-report/1`, §4) готовы; расхождение или нехватка листа — отказ с названием
   места. Отчёт квартала из уже собранного каталога — `--report <отчёт.json> --facts <каталог>`.
2. Файл отчёта → `reanchor.py --facts <отчёт.json>` (книга-кандидат, разложение скачка; его рабочие
   факты сверяются с кандидатом сборщика) → запись в `data/facts` тем же сборщиком: `--anchor <период>`
   без `--out` (якорь по умолчанию после этого — новый) → `--check` → `pytest tests/test_facts_*.py`
   (с `BANK_HANDOFF_DIR` — и маркер `archive`).
3. `calendar.json` и `peers.json` — правка руками с источником у каждого события и числа; после
   события — `confirmed: true`, после нового отчёта аналога — новые узлы и `as_of`.
4. Изменение состава полей — через `docs/INTERFACES.md` §3.2 (добавлением; ядро читает поля
   MODEL прил. B).
5. Шаблон листа следующего квартала: `python -B ops/tools/build_facts.py --check --sheet-template
   data/facts/sheets/<следующий период>.csv`, прежний шаблон удалить (тест `tests/test_facts_sheet.py`
   напомнит); `docs/FACTS.md` — числа нового якоря.

**Новая дивидендная политика или продление срока** (срок действующей — `dividends.policy.valid_until`). Истёкший
срок выпуск не останавливает — он несёт флаг `policy_expired`, пока в фактах прежняя политика. Что вносится:

| Случай | Факты | Книга |
|---|---|---|
| новое Положение | документ — в первичку (`research/primary/`, MANIFEST); параметры сборщика `POLICY_DOC`, `POLICY_APPROVED`, `POLICY_APPROVED_BY`, `POLICY_TERM_YEARS`, `POLICY_TERM_PAGE`, `POLICY_TERM_NOTE`; узлы `payout`, `threshold`, `divisor_src`, `text` в `build_dividends` — по пунктам нового документа; `DIV_FIRST_YEAR` — первый год прибыли новой политики (тест DPS идёт по годам действующей политики); событие Дня инвестора в `calendar.json` — `confirmed: true` | новая версия книги: блок `dividends` (A-D1), ядро не правится (MODEL §5.1) |
| срок продлён без нового документа | `POLICY_EXTENSION` — дата «по» и копия сообщения эмитента (решение Наблюдательного совета, существенный факт) в папке передачи: `valid_until` становится датой продления, `valid_until_src` и `valid_until_note` называют источник | не меняется |
| ни того, ни другого | ничего: срок по документу остаётся в фактах, выпуск выходит с флагом | не меняется |

После правки — обычная сборка (`--check`, тесты фактов) и запись решения в журнал версии книги.

## 4. Отчёт квартала: факты для сухого прогона перезаякоривания

До выхода отчёта перезаякоривание проверяют на **ожидаемом отчёте** — ожидании модели на закрываемый
квартал (MODEL §15.2: «факт = ожидание ⇒ механика ≈ 0»). Листов этапа 1 за этот квартал нет, поэтому
факты нового якоря строятся из закоммиченных фактов и **файла отчёта квартала** — того же файла, что
пишет `ops/tools/reanchor.py --expected` и читает `reanchor.py --facts` (формат `quarter-report/1`,
описание полей — `docs/REANCHOR.md`):

    python -B ops/tools/reanchor.py --expected <отчёт.json>                         # ожидание модели
    python -B ops/tools/build_facts.py --expected <отчёт.json> --out <каталог> [--facts <каталог фактов>] [--check]

Папка передачи не нужна. Пишет только в `--out` (в `data/facts` — отказ: ожидание — не факт); ручные
`calendar.json` и `peers.json` копируются как есть, чтобы каталог читался ядром целиком. Та же функция
доступна коду: `expected_facts(prev, report, name=…, sha=…)` — чистая, вход не меняет.

`reanchor.py` сам строит рабочие факты кандидата (узлы `calc: reanchor…`, без схемы и сверок); каталог
сборщика — те же числа в полях, которые читает ядро, но в каноне фактов: каждый узел с происхождением,
тождества и сверки, строки отчётности. По нему сверяют кандидата до отчёта, а после отчёта тем же
каноном становятся факты из листов (`--anchor`).

**Файл отчёта** (деньги — млрд ₽, ставки и доли — доли единицы, знаки ОПУ — как в МСФО, ОПУ и проценты — за
квартал; незнакомый ключ — отказ):

| Поле | Что это | Куда идёт в фактах |
|---|---|---|
| `period` | закрываемый квартал — следующий за якорем фактов (иначе отказ) | `anchor.period`, все `as_of` |
| `schema`?, `as_of`?, `published`?, `source`?, `note`? | `quarter-report/1`; конец квартала (сверка); дата публикации; чем построен | `anchor.expected.source` |
| `balance.books.<b>` | остаток книги на конец квартала (10 книг MODEL §4.1; кредиты — валовые, с кредитами по СС) | строки `balance.json`, `nii_books.books.<b>.balance_close` |
| `balance.loans_fvtpl`, `fvoci`, `fvtpl_bonds` | кредиты по СС (внутри `corp_loans`); долговые бумаги FVOCI с репо и облигации по СС (внутри `securities`) | `balance.loans_fvtpl`; `securities.fvoci_debt` + `fvoci_repo`; `securities.fvtpl_bonds` |
| `balance.{allowance, other_assets, other_liabilities, dividends_payable, bv_common, fvoci_reserve}` | резерв (величиной), прочие активы и обязательства (без дивидендов), дивиденды к выплате, капитал обыкновенных акционеров, фонд FVOCI после налога | `balance.allowance_ac` и одноимённые узлы; `capital.fvoci_reserve` |
| `balance.dividends_payable_year`?, `at1`?, `nci`? | год прибыли объявленного дивиденда; нет `at1`, `nci` — как на прежнем якоре | `balance.dividends_payable_year`, `balance.equity` |
| `interest.<b>` | проценты квартала по книге, величиной | `nii_books.books.<b>.interest_q`, `rate_anchor` |
| `dia` | взносы АСВ квартала величиной | `nii_books.dia_q`, `pnl.dia` |
| `pnl.*` | десять строк ОПУ квартала, которые читает ядро; `misc_net`? — иначе остаток до PBT; `oci_fvoci`?, `other_equity_movements`? | `pnl_quarterly.quarters.<период>` |
| `capital.{n20_0, n20_pre_dividend, n1_1_bank}` | нормативы на конец квартала; норматив до вычета объявленного дивиденда? | `capital.n20_0`, `n1_1_bank.value` |
| `capital.{basel_cet1, basel_rwa, bank_base_capital}`, `t2`? | величины, из которых ядро выводит вычеты якоря: `Ded20 = BV − basel_cet1`, `Ded11` — из `bank_base_capital`; нет `t2` — как на прежнем якоре | `capital.basel`, `bank_base_capital`, `t2_recognized` |
| `market.ofz_curve.{1, 3, 5, 10}`, `market.key_avg` | бескупонная кривая на конец квартала; средняя ключевая квартала | `capital.ofz_curve_anchor`; `nii_books.key_avg_anchor_q`, `pnl.key_avg` |
| `market.price_index`? | индекс цен квартала — правило книги, в факты не идёт | — |
| `mgmt.{nim, cor}`, `cir`? | упр. метрики квартала; нет `cir` — движок минус мост прежнего якоря | `mgmt_quarterly`, `bridge_mgmt_ifrs.<x>.history` |
| `shares.*`? | число акций, если изменилось | `shares.json` |

**Как строятся факты.**
* Каждое число отчёта — узел `{v, src, calc}`: `src` — «файл отчёта, путь поля, sha256», `calc` — «ожидание
  модели: …»; файл отчёта записан в реестр `anchor.documents` (`expected_report_<период>`), а
  `anchor.json` несёт блок `expected` и пометку в `note`. Округление — 6 знаков.
* Модель ведёт книгу одной суммой, отчётность — строками: остаток книги (за вычетом строк, заданных
  отчётом отдельно) делится на строки баланса (`commercial` / `project`; `consumer` / `cards` / `auto`;
  `ac` / `ac_repo`; три строки ликвидности; `corp_current` / `corp_term`; три строки опта) в долях
  прежнего якоря; `fvoci` — на `fvoci_debt` и `fvoci_repo` так же. Сумма строк равна книге точно.
* `nii_books`: начало квартала — конец прежнего якоря; `interest_q` — из отчёта; ставки —
  `rates_carry_residual: true` (§2); `other_interest_net_q` — остаток ЧПД вне книг (сверка: меньше 10 % ЧПД).
* Строки, которых модель не ведёт (комиссионные доходы и расходы раздельно, компоненты капитала,
  нормативы банка сверх Н1.1, квартал РСБУ), — `null` с причиной «нет данных: ожидаемый отчёт строку не
  несёт — …»; величины, которые модель не двигает (AT1, доля неконтролирующих акционеров, уставный
  капитал и эмиссионный доход, T2, минимум Н20.0 с надбавками), — как на прежнем якоре, с пометкой в
  `calc`.
* Мост упр. ↔ МСФО получает квартал: движок — по определению моста из фактов нового квартала, окно
  растёт на квартал. Мосты РСБУ → МСФО стоят по прежний якорь (ядро их не читает).
* `shares.json` (если отчёт не меняет), `dividends.json`, `guidance.json` — прежние (гайденс обязан быть
  на год нового якоря: смена года — только обычной сборкой из листов).
* Сверки (отказ, если не сошлись): активы = обязательства + капитал; PBT = сумма строк; PBT + налог =
  ЧП; остаток ЧПД вне книг меньше 10 %; вычеты `BV − basel_cet1` положительны; мосты упр. ↔ МСФО
  сдвинулись меньше чем на 0,1 п.п.

Тест — `tests/test_facts_expected.py` (в такте; папка передачи не нужна): схема и происхождение,
тождества, поля ядра, совпадение перечня полей отчёта с `reanchor.py`.

## 5. Лист квартала: что внести из нового отчёта и откуда

Новый отчёт МСФО приносит сборщику строки двух документов — отчётности и презентации. **Лист квартала** — эти
строки одним файлом в формате листов этапа 1: его можно заполнить руками по документу, если инструменты этапа 1
(разбор PDF) строку не дали, и по нему же проверить, что внесено всё. Шаблон следующего квартала лежит в
репозитории — `data/facts/sheets/<период>.csv`; заполненные листы — в папке передачи,
`stage1/quarter/<период>.csv` (канон фактов собирается только из папки передачи).

**Шаблон** пишет сборщик из журнала своих чтений на якоре: каждая строка листов этапа 1, прочитанная для
квартала якоря, понадобится и для следующего — с его метками периода.

    BANK_HANDOFF_DIR=<папка передачи> python -B ops/tools/build_facts.py --check --sheet-template data/facts/sheets/<период>.csv

| Колонка | Что это |
|---|---|
| `sheet` | лист этапа 1, куда идёт строка: `ifrs_history` (остатки на дату и нарастающие итоги — канонический ряд МСФО), `ifrs_anchor` (лист якоря), `ifrs_quarterly` (потоки за три месяца), `mgmt_kpi` (метрики презентации) |
| `metric`, `what` | метрика листа и её описание (словарь метрик этапа 1) |
| `period` | метка нового квартала: дата остатка (`2026-09-30`), квартал листов МСФО (`3Q2026`), нарастающий итог (`9M2026`), квартал метрик презентации (`2026Q3`) |
| `value`, `unit` | **что внести**: число в единицах листа (млрд ₽; проценты — как напечатаны, в процентах), знак — как в отчётности; десятичная точка |
| `doc`, `page`, `sha256`, `note` | документ (имя файла первички), страница PDF, sha256 документа (можно не вписывать — сборщик посчитает по файлу и сверит) и записка; квартал разностью нарастающих итогов — два документа, страницы и хэша через ` \| `, записка «расчёт: 9M2026 − 6M2026» |
| `prev_period`, `prev_value`, `prev_doc`, `prev_page`, `prev_note` | **откуда**: та же строка в прошлом отчёте — её значение, документ и страница; структура отчёта от квартала к кварталу почти не меняется, строка стоит в том же примечании |

Строка с пометкой «на прежнем якоре строки не было — необязательная» читается сборщиком как ноль или «не
раскрыто»: её вносят, только если она появилась в отчёте. Шаблон — по составу прошлого квартала: на годовом
отчёте (годовые раскрытия) и в первом квартале года (новый год гайденса) состав шире — недостающую строку
сборщик называет отказом.

**Заполненный лист.** Строка без значения ещё не внесена и не читается; у внесённой обязательны лист, метрика,
период, число и документ. Сборщик читает все листы `stage1/quarter/<период>.csv` не позже якоря и дополняет ими
листы этапа 1; строка, которая уже есть в листе этапа 1 с другим значением, — отказ (изменённую редакцию
вносят в сам лист). Остатки якоря в листе квартала заменяют отдельный лист якоря `ifrs_anchor_*.csv`.
Черновик вне папки передачи — `--sheet <файл>` вместе с `--out` (в `data/facts` с черновиком не пишут).

**Прочие входы квартала** — не ручной ввод, их готовят инструменты этапа 1 (сборщик печатает перечень с датами
вместе с шаблоном; то же — таблица «Привязано к якорю вне сборщика», §3):

| Вход (папка передачи) | Что должно появиться |
|---|---|
| `primary/`, `research/primary/` и их `MANIFEST` | отчётность МСФО, презентация, пресс-релиз квартала: файл, адрес, sha256 |
| `stage1/mgmt/guidance.csv` | гайденс года из презентации квартала (дата, слова, страница) |
| `stage1/calib/nii/data/nii_books_anchor_proposal.json` | пересчёт калибровки книг ЧПД на квартал якоря: разбиение процентов кредитных книг, льготная ипотека |
| `stage1/calib/capital/data/zcyc_quarter_ends.csv` | бескупонная кривая ОФЗ на дату якоря |
| `stage1/ras/` | формы ЦБ 0409101, 102, 123, 135 на 1-е число после квартала; релизы РСБУ трёх месяцев квартала |
| `research/facts/cbr_key_rate_changes.csv` | изменения ключевой ставки по конец квартала |
| `stage1/market/` | снимки ISS, если изменилось число акций; новое решение о дивидендах — строка листа решений `dividends_public.csv` и снимок брокерского календаря для сверки |

**День отчёта** (перезаякоривание — `docs/REANCHOR.md`): документы в первичку → строки отчёта и презентации
(инструменты этапа 1; чего они не дали — в лист квартала по шаблону) и прочие входы → `build_facts.py --anchor
<период> --out <каталог> --report <отчёт.json>` → `reanchor.py --facts <отчёт.json>` → запись фактов
(`--anchor <период>`), `--check`, тесты → шаблон следующего квартала (§3, порядок, п. 5).

Тесты — `tests/test_facts_sheet.py`: шаблон в дереве — на квартал после якоря и ссылается на отчёт якоря; с
папкой передачи — шаблон воспроизводится байт в байт, а сборка следующего квартала из листа, заполненного по
шаблону, не просит ни одной строки вне его.
